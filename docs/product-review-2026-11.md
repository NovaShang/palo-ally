# Palo 产品梳理（原 PaloAlly）（2026-11-21）

## 一、它是什么

一句话：**你日常用 Claude Code 的地方**。有一个助理 Palo 替你管事，几个长期跑着的会话替你干活。Mac 上是工作台，手机上是对话、等你的事和随手交代。家里人也能用。

这句话之外的东西都要能挂到它上面，挂不上的就是失控的来源。

## 二、现在有多少东西

5 周 317 次提交，App 约 7.4 万行 Swift，电脑端约 2.5 万行 TS。概念按用途分组：

| 组 | 现在有的 |
|---|---|
| 谁在干活 | Palo（助理）、Pal（PaloAlly 托管的会话）、外部会话（电脑上别处开的 CC）、Ally（家人朋友的代理）、工作区（会话的组） |
| 谁在等你 | 问题卡、权限卡、提议卡（开会话 / 接管）、Ally 草稿、需要你的任务、等你的事列表、横幅、球球角标、侧栏黄点、推送、晨报里的提醒 |
| 产出 | 成果库（产出物库）、文件树、文件预览、文件编辑、网页标签、文档卡片分屏、TL;DR |
| 输入 | 打字、按住说话、Mac 右键说话、分享扩展、引用回复、回到这里重来 |
| 连接 | 云端中转、本机 / 局域网 / Tailscale 直连、多台电脑 |
| 设置和详情 | 球球面板（此刻）、会话详情、关于这个会话、设置、电脑与设备 |
| 正在设计 | Backlog |

## 三、失控在哪（症状）

1. **名词重叠。** 「Pal」「会话」「外部会话」在你眼里是一回事，在代码和界面里是三种，行为也不一样（能不能发消息、有没有详情、算不算等你）。「成果」「产出物库」「文件」也有交叉。等你的东西有 5 种卡片，外加列表、横幅、角标、黄点 4 个入口，上周才把它们的数字对齐。
2. **入口重复。** 同一件事有好几个按钮：右侧栏的 3 个关闭（昨天删了 2 个）、球球面板、详情、关于三处都能看会话信息、「收起」和要做的「以后再说」。
3. **每个功能乘以 6。** 手机、iPad、Mac 三个平台，乘以普通页面和工作区小窗两种布局。一个功能就有 6 种组合，大部分只在一两种组合里走过。崩溃多半就出在没走过的组合里：Mac 悬停、Mac 选中文字、手机打开某个会话……一共修过 9 次崩溃，现在还在崩。
4. **一个反馈一个功能，当天上线。** 很多功能是一句话进来、当天做完、装到你手机上，没有回头验收。待你在真机上确认的清单一直很长（直连、等你的事、Office 预览、iPad 宽度……）。
5. **发不出正式版。** 公开版停在 0.1.18，家里人拿到的修复要靠开发通道。

根子是：**加东西的速度远大于收口的速度**，而且没有一个「这个功能该不该有、该挂在哪」的判断标准。

## 四、建议的核心模型

只留四个名词，两条流向。新功能必须能说清楚它属于哪一个；说不清就不做。

**四个名词**（第一版，用词已按下面「结构和用词」改定）
- **助理**：管事，不干具体的活。
- **agent**：一个 Claude Code 会话，不管是不是在这里开的。Pal 和外部会话合并，区别只是「能不能在这里发消息」这一个开关。
- **工作区**：几个 agent 放在一起，加一份 backlog。
- **成果**：agent 和助理做出来的东西（页面、文件、报告）。文件树是看成果的另一种方式，不是另一个概念。

**两条流向**
- **你 → AI**：消息（现在说的）、backlog（以后再做的）。
- **AI → 你**：回复（在对话里）、等你的事（要你定的）、成果（做出来的）。

按这个模型，等你的 5 种卡片在界面上是同一种东西的不同样子；横幅、角标、黄点只是同一个数字的三个显示位置。

### 结构和用词（11-21 定的）

助理 → 工作区 → agent → 子 agent。中文界面用「助理」「工作区」「agent」「子 agent」；英文用 Assistant / Workspace / Agent / Subagent。

| | 助理 | 工作区 | agent | 子 agent |
|---|---|---|---|---|
| 是什么 | 一个 agent，管事 | 一组一起干一件事的 agent：共用 backlog、一起归档，并排怎么摆是它的显示方式 | 绑一个文件夹，长期推进一块活 | agent 或助理临时派出去的 |
| 活多久 | 永远 | 事情做完归档 | 几天到几个月 | 一件事做完就没了 |
| 上下文 | 自动压缩，一直延续 | | 跟 Claude Code 本来的一样 | 用完就丢 |
| 你管不管 | 跟它说话 | 排 backlog、加减 agent | 跟它说话 | 不管，只在派它的那一个下面看进度 |

- 原则：不造词，用大家已经在说的词；我们的主张放在结构里（谁活多久、怎么分组、backlog 跟谁），不放在名字里。不再用 Palo / Pal / Ally 这类名字。
- 不叫 project：Claude Code 里 project 指一个文件夹，会打架。
- 只有一个 agent 的工作区，侧栏里看不出这一层。
- 终端里开的 Claude Code 会话也是 agent。
- 现在的 Ally 改叫「好友」（Contacts）：别人的助理，像加微信好友一样当面互加；它来的话只是消息，助理替你回的每句都要你点头。「我的」这种身份去掉（自己的其他电脑归「电脑与设备」），好友只指别人。
- 其他用词（11-21 定）：
  - **成果**：唯一叫法（不再说产出物库、产物库）。
  - **任务**：只指后台在跑的东西（子 agent、后台命令）。需要你的事都进「等你的事」；待办提醒不叫任务。
  - **主机**（Host）：跑 agent、管数据的那台机器；手机和 iPad 叫**设备**。「电脑与设备」改「主机与设备」。
  - **详情**：一个 agent 的信息只有这一个入口（合并详情、关于这个会话、此刻、球球面板）。
  - **归档**：「先不看了」只有这一个词（合并收起、更早的会话）；等你的事里的「收起」改成「以后再说」，挪进 backlog。
  - **backlog**、**agent** 不翻译。
  - **等你的事**，英文 Waiting on you。
  - 晨报、晚报保留。
- **产品名**：Palo。App Store 名「Palo: Assistant & Agents」（中文区「Palo：个人助理和 agent」），主屏只显示 Palo，内部也叫 Palo。卖点：做助理，比个人助理更能干；做工具，比生产力工具更顺手。助理在界面上泛指时叫「助理」，新用户的助理默认名字还是 Palo，可以改。

## 五、平台分工

| | 做什么 | 不做什么 |
|---|---|---|
| Mac | 工作台：工作区分屏、右侧栏（文件、成果、网页、等你的事、backlog）、编辑文件 | |
| iPad | 跟 Mac 同一套布局 | 不单独设计 |
| 手机 | 对话、等你的事、随手加 backlog、看成果 | 工作区分屏、编辑文件、文档卡片 |

手机明确少做，6 种组合就降到 3 种左右。

## 六、接下来两周的建议

1. **先停新功能**，backlog 也往后放。
2. **稳定性**：把崩溃一个个找到根因。先拿到手机上「羿云人脸评估」那次崩溃的报告。再定一张固定的冒烟清单（每个平台 × 每种布局各点一遍），每次发版前跑一遍。
3. **收口验收清单**：这两周加的东西你逐个在真机上点一遍，不行的修或删。
4. **合并名词**：Pal 和外部会话合并成「会话」；球球面板、详情、关于合成一个「会话详情」。
5. **发一次正式版**：需要你续签苹果开发者协议。

之后的新功能，动手前先写一页：属于四个名词里的哪个、走哪条流向、在三个平台上各是什么样。你点头再做。

## 七、需要你定的

1. 认不认这四个名词，特别是把 Pal 和外部会话合并。
2. 手机端明确少做这条，接不接受。
3. 停两周新功能先做稳定性，行不行。
