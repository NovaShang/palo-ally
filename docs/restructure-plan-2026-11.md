# 从现在到线框稿：改动规划（2026-11-22）

目标状态见 `docs/workbench-design/structure-wireframe.html` 和 `docs/structure-proposals-2026-11.md`。
时间是我做的估算（含 Mac、iPhone 模拟器、你的真机各走一遍）。

## 总原则

- **只改用户看得到的，内部标识不动。** bundle id、仓库名、代码里的类型名（Pal、Ally、host）、存储文件名都保持原样，避免配对、更新、数据迁移出问题。界面文案、App 显示名、提示词里的称呼改新词。
- **主机改动只加不减。** 家里人还在用旧版 App，主机新增 RPC 和字段，旧的继续认；去掉的东西（TL;DR）旧版点了也只是没反应，不会崩。
- **一批一交付。** 每批做完：冒烟清单（侧栏点一遍、打字、详情、右侧栏、手机）→ 装你的 Mac 和手机 → 你验收 → 下一批。
- **先修手机那个崩溃。** 「羿云人脸评估」一打开就崩，没查清之前不往上堆改动。需要你把手机连上这台 Mac。

## 第 1 批：用词和删减（约 5 到 6 小时，风险低）

| 改什么 | 在哪 |
|---|---|
| App 显示名 PaloAlly → Palo | `project.yml` 的 CFBundleDisplayName（App 和分享扩展），InfoPlist.xcstrings |
| 界面里泛指时称「助理」，具体那一个用它的名字（新用户默认叫 Palo，可以改） | App 里写死「Palo」当泛称的地方；setup 默认名不变 |
| Ally → 好友（Contacts） | App 文案、侧栏分组、加好友流程、主机提示词和通知文案 |
| 去掉好友的「我的」身份 | App 里不再给这个选项；主机仍接受旧值，已有的照常显示 |
| 电脑 / 电脑端 → 主机；电脑与设备 → 主机与设备 | App 文案、主机通知和提示词 |
| 产出物 / 产物库 → 成果 | App 文案、主机工具说明（Artifact 工具的描述） |
| 任务只指后台在跑的；「办过的事」→「记录」 | App 文案 |
| 删 TL;DR | App：TldrViews、按钮和弹页；主机：chat.tldr 和相关提示词（RPC 保留空实现，旧版不报错） |

文案在 4 个字符串表里（Localizable、Library、Files、InfoPlist）加主机 i18n，中英文一起改。

## 第 2 批：一种 agent、归档（约 8 到 10 小时，风险中）

**侧栏**：「会话」分组改名「agent」，Palo 开的和外部会话同一种行；终端还开着的标「终端里开着」；底部一行「已归档 N」。

**外部会话变成能打字的 agent**
- 主机：给没接手的会话发消息时，自动走现有的接管流程；终端还持有文件就把消息排队，等它退出（现成的 exit-in-terminal 等待），退出后接手并发出。排队可取消。保证不会两边一起写 jsonl（现有的 holders 检查不变）。
- App：SessionPage（只读页）去掉，统一用 agent 的对话页；输入框在排队时显示「终端那边退出后发出 · 取消这条」；「接管」按钮去掉。

**归档**
- 「更早的会话」（一阵子不用自动收起）改叫归档，规则不变。
- 「结束这个会话」改成「归档」。
- 「从历史记录继续」合进「已归档」列表：主机上所有 Claude Code 会话都能搜到、拿回来。
- 等你的事里的「收起」先隐藏，第 5 批换成「以后再说」。

## 第 3 批：详情一层、agent 的记忆（约 6 到 7 小时，风险低）

- 助理：PaloDetailForm + AssistantView（关于助理）合成一页：现在（后台任务、上下文）/ 定时（WatchesSection 搬过来）/ 设置折起（名字颜色、语言、模型、记忆）/ 记录（TasksSection 改名）/ 让助理停下。
- agent：AgentDetailView + 「关于这个会话」合成一页：现在 / 设置折起（名字、模型、权限、记忆、工作区）/ 记录 / 归档。
- agent 的记忆：主机 memory.list/read/write 加一个可选的 agent 参数，读写它文件夹的 CLAUDE.md 和 Claude Code 给这个目录记的项目记忆；沿用助理的「刚被改过」冲突检查。App 复用 MemorySection。
- 详情里不再有「等你」那一行。

## 第 4 批：等你卡和右侧栏的「等你」（约 6 到 8 小时，风险中）

- 一种卡：QuestionCard、ApprovalCard、HelperProposalCard、好友草稿卡改用同一个外壳（谁 · 要定什么 · 一句背景 · 选项），各自的按钮动作不变；答过折成一行。
- 右侧栏固定标签「等你」：助理里看全部，agent 里只看来自它的（列表已有按 agent 过滤）。横幅和角标点了打开这个标签。
- 手机：侧栏页里加「等你」标签，底部弹出的列表保留给横幅。
- ⌘⇧I 打开这个标签。

## 第 5 批：待办（约 10 到 12 小时，风险中）

- 主机：按文件夹存，`~/.paloally/state/backlog/` 下每个文件夹一份 Markdown（一行一件，顺序即先后，正在做的标 agent，做完的放末尾）。RPC：list / add / move / assign / start / done / remove，变化时推事件。
- agent 和助理的工具：加一件、看列表、标完成；提示词里一句「主人说放待办就用它」。助理那份用它自己的目录。
- App 右侧栏「待办」标签：正在做 / 排队（前三件正常，后面一行一件）/ 做完折叠；拖动排序；指给某个 agent；底部加一件。手机长按拖动。
- 「下一件」：agent 一轮做完、没有等你时，输入框上方显示「下一件 · 开始 · 换一件」；开始 = 把这件作为引用发给它并标正在做。忽略一次当天不再提示。
- 等你的事里的「以后再说」：把这件挪进对应文件夹的待办。

## 第 6 批：右侧栏收尾（约 2 到 3 小时，风险低）

- 固定四个标签，顺序：等你 · 成果 · 待办 · 文件；打开的文件、网页排在后面。已存的标签状态按新顺序整理一次。
- 成果跟着你在哪儿：助理里看全部，agent 里看它的，一键切全部。

## 合计

约 37 到 46 小时，分 6 批。第 1、3、6 批改动面小，第 2、4、5 批要多花时间在测试上。

## 不在这次范围

- 工作区（你说先不动）。
- 平台分工、右侧栏的标签模式。
- 内部改名（代码、bundle id、仓库）。
- 发正式版（还卡在苹果开发者协议）。

# 代码结构部分（11-22 加）

两路排查（主机、App）的结论和据此加进各批的工作。只读排查，代码没动。

## 排查发现

**好的一面**
- App 的数据层已经是一个类（AppStore 分助理 / agent / 外部会话三种范围），发消息、流式、回到这里重来、卡片大多共用。
- 主机已经有一层 HarnessDriver（`harness/claude.ts`），开进程、发消息、权限回调、MCP 工具都在它后面。
- 等你的事、成果、权限和提问的存储已经共用；App 调用的 104 个 RPC 都还有人用（只有 audit.tail 只给命令行用）。

**重复最多的地方**

| # | 重复 | 位置和规模 | 合并难度 |
|---|---|---|---|
| 1 | 助理和 agent 的运行时各写一遍：事件处理、启动、卡住重发、停止、任务跟踪 | 主机 `conversation.ts`（939 行）和 `palSession.ts`（1451 行），外加 `tasks.ts` 和 palSession 里的一份 | 大，风险高 |
| 2 | 读历史三套：外部会话、agent、还有一份内联分页 | 主机 `ccSessions.ts`、`palHistory.ts`、`transcriptTail.ts`；App 外部会话还留着一条没人用的历史路径（约 120 行） | 小到中 |
| 3 | 等你卡五种，各自有状态和外框；列表里的行和对话里的卡也是两套；计数五种算法 | App 约 1100 行（QuestionCard、ApprovalCard、HelperProposalCard、PalAdoptCard、好友草稿卡、PendingViews） | 中 |
| 4 | 详情：助理和 agent 两套表单、两套「关于」，模型选择器三个、两种数据格式 | App 约 700 行；主机换模型 / 思考深度两套（助理这边还少一个校验） | 中 |
| 5 | 状态文字和圆点约六个版本 | App 约 250 行；主机三种状态结构 | 小到中 |
| 6 | 发消息和引用：助理支持引用、斜杠命令，agent 不支持；附件处理也不同 | 主机 `hub.ts` 和 `pals.ts` / `palSession.ts` | 中 |
| 7 | 回到这里重来两套；助理多出的代码只因为它的历史不是从 transcript 读 | 主机 `hub.ts` 和 `palSession.ts` | 中 |
| 8 | 「X 在等你」推送、权限卡文字、各种小工具函数（pidAlive×3 等）各写几遍 | 主机多处 | 小 |
| 9 | 好友对话是独立的一整套聊天界面和存储，没用上主对话的滚动、输入框、语音 | App 约 630 行 | 大，用户可感知 |
| 10 | 标题的水滴（助理）和胶囊（agent）是同一件事画了两遍 | App 约 800 行 | 先要定设计 |
| 11 | 演示主机（3900 行）把上面的助理 / agent 分裂又复制了一遍 | Kit Demo/ | 每次合并都要同步改，约多 30% 工作量 |
| 12 | 外部会话变成 agent 以后，跟踪终端会话的大部分代码可以删 | 主机 `handoffs.ts`（576 行）、`sessions.list`、`pals.recent` | 中 |

**死代码**：App 的 SessionRow、AllyRow、AdoptFlowSheet，外部会话的旧历史路径；TL;DR 主机约 45 行、App 约 330 行（旧 transcript 里留一个过滤，免得看到原始标记）。

**写死 Claude Code 的地方**
- 主机：transcript 文件在约 12 个模块里直接读；SDK 的 getSessionMessages / forkSession / listSessions 绕过了 HarnessDriver；hooks 和设置文件、CLAUDE.md 和项目记忆路径、登录、模型和思考深度列表（两处硬编码）、工具名字符串判断、压缩、回到这里重来的 uuid 都是 Claude Code 专有的。
- App：登录页、模型名解析（按 claude-家族-版本）、思考深度和权限模式的固定列表、「/exit」「claude --resume」等文案、问题卡按 AskUserQuestion 的格式建模。

## 新加第 7 批：harness 适配层和运行时合一（约 20 到 28 小时，风险高）

放在 1 到 6 批之后：前面几批把界面和用词理顺、删掉一半重复，这一批改的是地基。

- **一个 AgentSession**：`conversation.ts` 和 `palSession.ts` 合成一个类，差别变成开关：自动压缩、好友消息把关、提问进等你的事、可以睡。助理就是开了这些开关的 agent。
- **把 Claude Code 关进适配器**：transcript 读写、SDK 的会话函数、hooks 和设置、记忆路径、登录、模型和思考深度、压缩、回到这里重来，都移到 `harness/claude/` 下面，上面只认统一的接口（开进程、发消息、事件、读历史、能力清单）。
- **能力清单发给 App**：每个 agent 带一份「它的 harness 支持什么」：名字、怎么登录、模型和思考深度、权限模式、能不能回到这里重来 / 压缩 / 接手终端、命令前缀。App 里那些写死的列表改成读这份清单。
- **不写第二个适配器**：接口划好，Codex 这类等真要接时再写。
- 助理的历史暂时还用自己的 chat.jsonl，不改成读 transcript（那会动到所有老数据），记成以后的选项。

## 这次不做

- 好友对话并进主对话界面（大改，用户能感觉到，先不动）。
- 标题水滴和胶囊合一（要先定设计）。

## 以后不再长歪的几条规矩

1. 新的「等你拍板」一律做成 PendingItem，不再单独做卡片和计数。
2. App 里不出现 Claude 专有的名字和列表，都从主机的能力清单来。
3. 助理和 agent 的功能只写一遍；真有差别就加开关，不复制。
4. 演示主机跟着真主机一起改，同一个提交里。
5. 每批发版前跑冒烟清单（Mac、iPhone 模拟器、真机）。
6. 动手前一页说明：属于哪个名词、走哪条流向、三个平台各是什么样。

## 合计

原来的 6 批约 37 到 46 小时，加上结构工作约 17 到 22 小时，再加第 7 批约 20 到 28 小时，一共约 74 到 96 小时。
