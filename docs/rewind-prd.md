# PaloAlly · 回到这里重来 PRD

2026-10-16。

## 1. 一句话

长按自己发的一条消息（Mac 上右键），选「回到这里重来」：对话回到这条之前，之后的内容从模型的上下文里撤掉，这条的文字回到输入框，改了再发。

## 2. 已定（主人定）

1. **入口：**自己消息的菜单里加「回到这里重来」，和「复制」在一起。
2. **范围：**Palo 和 Pal 都能用。
3. **只有 Pal 可以把代码也恢复：**文件回到这条消息之前的样子。
4. **对话以外已经做过的事不撤销：**发出去的消息、邮件、推送、给 Ally 的话、Palo 这边写的文件。确认里用一行说明。

## 3. 交互

- **确认在原地出现，**不是弹窗，占输入框的位置：
  - 「回到这里重来？之后的对话会被撤回，已经做过的事不会撤销。」
  - 「重来」（主题色）和「算了」；
  - 要撤回的那些消息变淡。
- **Pal 多一个开关「代码也恢复到那时」：**默认关，只有主机说能恢复时才出现。不能恢复时显示一行「这一步之前的代码没法恢复」。
- **正在忙时：**确认里说「它还在忙，重来会先停下这一轮」，点「重来」先停再重来，对主人是一步。
- **重来以后：**之后的消息淡出，这条的文字进输入框并聚焦。
- **不显示这一项的消息：**
  - 别人说的话（Palo 对 Pal 说的、别的会话发来的）；
  - Palo 里的斜杠命令；
  - Palo 里早于这个功能、又在记录里对不上的消息。

## 4. 主机

### 4.1 用 Claude Code 自己的机制

- **对话分叉成一个新会话，原会话的记录原样保留：**
  - 下次启动用 `resume: 原会话` + `forkSession` + `sessionId: 新 id` + `resumeSessionAt: 这条消息在记录里的上一条`；
  - 新 id 立刻记下（Palo 在 runtime.json，Pal 在它的记录里），名字、花费照旧。
- **待分叉：**Claude Code 到新会话的第一条消息才写记录。在那之前主机记着「原会话、分叉点、新 id」，每次启动都按它分叉，直到新记录出现。重启主机、Pal 睡下再叫醒都不丢。
- **代码（Pal）：**
  - Pal 从现在起开 `enableFileCheckpointing`，只有之后的轮次能恢复；
  - 恢复时主机先停掉 Pal，用原会话起一个不说话的进程，调 `rewindFiles(这条的 uuid)`，关掉，再分叉；
  - 记录里没有这条的文件快照，或恢复失败：报「这一步之前的代码没法恢复」，对话不动。
- **分叉点在最近一次压缩之前：**Claude Code 只从最近一次压缩往后接着跑，`resumeSessionAt` 找不到那条（报 No message found）。这时改用 SDK 的 `forkSession(原会话, {upToMessageId: 分叉点})` 立刻抄一份到新会话，直接 resume 它。抄出来的 uuid 是新的：Palo 的 chat.jsonl 跟着换，Pal 的页面重新读一次。
- **2026-10-16 实测（haiku）：**
  - 我们给的 uuid 就是记录里那条的 uuid；
  - 分叉后消息的 uuid 不变，文件快照跟着分叉走；
  - 换一个进程照样能恢复文件；
  - 压缩之前的点用 `forkSession` 抄一份，接着聊，模型只知道那之前的事（live test）。

### 4.2 消息和记录对上

- **Pal：**消息 id 就是记录里的 uuid。
- **Palo：**
  - 主人的消息在 chat.jsonl 里多一个 `uuid`，就是交给 Claude Code 时用的那个；
  - 以前的消息，主机启动时在当前会话的记录里按原文和时间对一次（最近 300 条），对上的补上 `uuid`；
  - 对不上的不能重来。

### 4.3 撤回

- **Palo：**这条和之后的消息在 chat.jsonl 里标 `rewound: true`，留着备查，不再出现在 sync、history、搜索里。
- **Pal：**对话本来就从会话记录读。新记录出现前，从原会话读到分叉点为止。
- **事件 `chat.rewound {id, ids, pal?}`：**App 把这条和之后的都拿掉。
- **重连：**断线时撤回的，`sync{sinceSeq}` 的 `rewound` 里带着这些 id。
- **审计：**每次都记 `chat.rewind` / `pal.rewind`。

### 4.4 忙的时候

- 主机拒绝：「它还在忙，先停下再重来」。App 先调停止再重来。
- Palo 的「忙」：有在跑的一轮、没回的话、Ally 那一轮、后台任务。
- Pal 的「忙」：有在跑的一轮、没收下的话、在等主人的卡片、正在起来。

### 4.5 接口

| 方法 | 参数 | 返回 |
|---|---|---|
| `chat.rewind` | `{messageId}` | `{text}` |
| `pals.rewind` | `{id, messageId, restoreFiles?}` | `{text, filesRestored}` |
| `pals.rewind` | `{id, messageId, check: true}` | `{canRestoreFiles}` |

- `ChatMessage` 新增 `uuid?`：Palo 里主人的消息，有它才能重来。
- `sync` 新增 `rewound?: string[]`。
- 新事件 `chat.rewound`。

## 5. 不做

- 撤销对话以外的事。Claude Code 的自动记忆（memory 文件夹）也算对话以外，不撤销。
- 带图片或附件的消息：重来时只有文字回到输入框。
- 记录里对不上的老消息。

## 6. 验收

1. Palo：重来以后问刚才说过什么，模型不知道撤回的内容。
2. Pal：第二轮改了文件；回到第二轮之前并恢复代码，文件回到第一轮后的样子，模型不记得第二轮。
3. 压缩过以后回到压缩之前的一条，照样能接着聊。
4. 正在忙时点「重来」，先停下再重来。
5. 重来以后重启主机、让 Pal 睡下再叫醒，都还在新的分支上。
