# Palo 结构优化方案（对应导航图的 8 个问题）

每条给出推荐做法和备选，你决定采不采纳。时间是我做的估算，含三个平台各走一遍。

## 1. agent 分成两种（Palo 开的 / 外部会话）

- **推荐：合并成一种 agent，同一个页面。** 外部会话也能直接打字；第一次发消息时自动接手（现在的「接管」按钮去掉）。还在终端里跑着的，标题下标一句「终端里开着」，发之前提醒一次「会在这里接手，终端那边停下」。
- 备选：页面合并，但外部会话保持只读，要说话仍点「接管」。
- 约 4 到 6 小时。

## 2. 等你的东西在对话里和列表里各一处

- **推荐：两处都留，但只有一种卡片样子。** 对话里的卡片是看上下文时顺手答的地方，列表是总入口；答了任何一处，另一处同时收起（现在已经这样）。提问、权限、提议、好友草稿统一成同一种「等你卡」：一行谁、一句要定什么、选项按钮。
- 备选：对话里不再放卡片，只留一行「等你：…  →」，点了去列表答。少一处，但看上下文时要跳走。
- 约 3 到 4 小时。

## 3. 「要做的事」散成三样（目标和定时 / 办过的事 / backlog）

- **推荐：分成「要做」和「记录」两块。**
  - 要做：backlog（排队、没时间）和定时（到点做、可重复，现在的「目标和定时」）放在一起，都在工作区里；助理那份放杂事和晨报这类定时。
  - 记录：现在的「办过的事」改叫「记录」，放进详情；「任务」这个词还给后台在跑的。
- 备选：定时保留在助理的「关于」里不动，只做 backlog 和改名。
- 跟 backlog 一起做，约 6 到 8 小时（含 backlog 本身）。

## 4. 工作区只是布局

- **推荐：工作区有自己的一页。** 里面是它的 agent、backlog（含定时）、成果、归档；Mac 上并排的卡片是这一页的「并排看」模式。手机打开工作区就是这一页，不再只是 agent 列表。
- 备选：只给工作区加 backlog，其他不动。
- 约 5 到 6 小时（不含 backlog）。

## 5. 详情有两层（详情 → 关于）

- **推荐：合成一层。** 上面是「现在」：等你、在做、上下文；下面是「设置」：名字和颜色、模型、权限、记忆、语言，默认折起。助理和 agent 用同一个结构，只是助理多几项。
- 备选：保留两层，只把第二层统一叫「设置」。
- 约 3 小时。

## 6. 「先不看了」有三种说法

- **推荐：只有「归档」。** 一阵子没用的 agent 自动归档（现在的「更早的会话」）；「结束这个会话」改成「归档」；历史记录里只分「在用」和「已归档」；等你的事的「收起」改成「以后再说」，进 backlog。归档的随时能拿回来。
- 备选：只改名字，行为不动。
- 约 2 到 3 小时。

## 7. 成果的范围不清

- **推荐：跟着你在哪儿走。** 在助理那里看全部；在工作区看这个工作区的；在某个 agent 看它的；都能一键切「全部」。
- 备选：永远默认「全部」，用筛选缩小。
- 约 2 小时。

## 8. agent 看不到自己的记忆

- **推荐：agent 详情里加「记忆」，跟助理一样能看能改**（它文件夹里的 CLAUDE.md 和 Claude Code 给这个项目记的东西）。
- 约 1 到 2 小时。

## 建议的顺序

先 1、6、8（简单，侧栏马上清楚），再 5、2（详情和等你），最后 4、3、7（工作区那一套，和 backlog 一起）。全部约 26 到 34 小时。按我们说好的，先停新功能，这些属于收口，可以在两周里做。

## 继续梳理（11-22）

- TL;DR 删掉。
- 平台分工保持现状。
- 右侧栏基本不变（多一个 backlog 标签）。
- 线框稿：docs/workbench-design/structure-wireframe.html
- backlog 的中文叫「待办」（英文 backlog）。
- 右侧栏固定的三个标签按这个顺序：成果、待办、文件。「等你的事」不常驻，从横幅或角标打开时才出现，跟打开的文件、网页一样是临时标签。
- 等你的事改成右侧栏的常驻标签（11-22）：在助理那里看全部，在某个 agent 那里只看来自它的。右侧栏固定四个标签：等你 · 成果 · 待办 · 文件（等你带数字）。详情里不再放「等你」那一行。
