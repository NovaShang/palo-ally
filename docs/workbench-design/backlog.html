Backlog：排好队、轮到了再做

「等你的事」是 AI 等你，要快；Backlog 是你想让 AI 做、还没轮到的事，有顺序、不催。每个工作区（和单独的会话）一份，Palo 自己一份放杂事。主要派给 agent 做：会话空下来时，底部提示下一件，你点「开始」它才做。

  • 三样东西的分工
    方向急不急打扰你吗
    等你的事AI → 你（它卡着）尽快横幅、角标、卡着的推送
    Backlog你 → AI（排队）不急，有顺序不打扰：无角标、无推送
    提醒 / todo到点了 → 你有时间点到点提醒
  • 归属：侧栏一级的东西各有一份：每个工作区、每个不在工作区里的会话、Palo。顺序只在一份之内有意义。
  • 存法：一份一个 Markdown 文件（~/.paloally/backlog/<工作区>.md），一行一件，从上到下就是顺序；正在做的标出是哪个会话，做完的打勾留在文件末尾。agent 拿到路径就能直接读写，不需要新的协议；App 读同一个文件，拖动排序就是改文件里的顺序。
  • 怎么加进来：①在任何会话里说「这个放 backlog」，agent 写进这个工作区那一份，对话里留一行「已放进第 N 件 · 撤回」；②右侧栏 Backlog 底下直接打字；③「等你的事」里不急的事点「以后再说」挪进来（取代现在的「收起」）。
  • 怎么开工：工作区里有会话空下来（做完一轮、没有等你的事），输入框上方出现「下一件：… · 开始 · 换一件」。点「开始」，这件就作为你的话发给这个会话，并移到「正在做」；它做完、你确认了才打勾。默认不自动接着做；以后可以给某个工作区单独打开「做完自动接下一件」。
  • 顺序归你：拖动排序。agent 可以建议调整（Backlog 顶上一条建议，接受 / 不用），自己不能改。前三件正常显示，后面的折成一行一件的小字。
  • Palo 的那份：放不属于任何项目的杂事。Palo 空闲时不主动提示，晨报里带一句「backlog 第一件是…」。
  • 不做的：截止日期、优先级字段、标签。要定时间的东西是提醒，不是 backlog。

还没定、你可以改的

  • 会话空下来时的「下一件」提示：每次空闲都出现，还是你忽略一次就当天不再出现？我倾向后者。
  • 做完之后：agent 自己说「做完了」就打勾，还是要你确认？我倾向它打勾、你可以撤回，省一步。
