# 工作台：需求和主人的原话

2026-10-19。工作台第一版的实现已撤回（代码保留在 `workbench` 分支），这里只记需求和主人的原话，不写实现。完整的产品需求见 `workbench-prd.md`，当时的分期计划见 `workbench-plan.md`，设计稿在 `workbench-design/`（`workbench.html` 总体布局，`details.html` 详情页，`indicator.html` 会话指示器）。

## 方向

- 「我打算逐渐退役 bento term 了，我不觉得 cli 一直是个好的选择。」
- 「我个人我是需要一个个人助理，一个我日常的工作环境来让我很好的用 Claude Code。」
- 「我想照顾用 claude code 但是不用官方订阅的人。」
- 「注意复用或者复制现在已经有的东西。现在有些东西已经布局，已经是千锤百炼的东西，没必要改。」
- 技术和工作量都不是问题，只讨论产品：「我跟你说这些只是告诉你，技术上没有问题，工作量上也没有问题，我们只需要关注产品设计。」

## 布局（Mac 和 iPad 一样）

- 「左侧有一个跟 Mac 大部分软件差不多的导航侧栏，然后导航侧栏的第一项是这主页面。主页面这个导航项特别的大。嗯，然后那个我的那小球的动画也在那里。」
- 「右侧就是一个到顶的……对话区，跟现在差不多。这是选中主 agent 的时候状态。」
- 「非主 agent 的时候，就更接近 Bento Term 的感觉。」
- 「左侧导航是一棵树。最顶上是每个版，直接点这个版打开的就是这个版拼贴的所有会话。然后你也可以展开这个树，下边列出的会话里点击一个，那就是只打开这个会话的状态。这会儿的布局就跟主 agent 有点像了。」
- 「左边导航栏最下边是 Allies，就是现在的这个好友的功能。然后右边面板是一个浏览器。」
- 会话的分组：「默认建立普通的会话（不在板上），可选地建立板或者把会话加到某个板上」。名字定为「工作区 / Workspace」：「板这个词太不合适了」。
- 「建工作区还需要更可见的入口除了拖动。」
- 在工作区里关掉一格：进入历史会话。
- 右侧浏览器面板：默认收起，用到时弹出。
- 新建会话：弹出最近用过的文件夹列表。
- Mac 上说话：「使用现在 palo 的 composer，长按说话」。
- 「我要 ui 的沉浸感。就是遵循 liquid glass 的原则的基础上，让对话内容在滚动的时候撑满上下。」
- 「Mac 和 iPad 版应该支持多窗口。」

## 标题和指示器

- 「palo 和 pal 的对话界面（包括右上角）应该是一模一样的。另外每个 agent 都要能打开它的详情面板。包括设置模型 effort，看 tasks 等所有功能都要在里边。」详情由点标题弹出，不放右侧栏。
- 「mac 的 palo 页面，右上角应该只保留一个侧边栏按钮。」
- 「会话的状态胶囊改成一个圆形的指示器。是一个复合的圆形图标。中心是这个会话的状态图标（参考 bentoterm 的图标和配色），外边大半个圆弧是 context window 情况，下方是小字 low/med/hi/xhi/max，字不同颜色代表不同模型。样式可以参考 iphone 的状态图标。」
- 「中心图标和外边的 pie 要绝对同心。下边的文字需要用更圆润的字体。」「指示器和玻璃球没有同心。」
- 模型颜色：「模型使用冷色到暖色的阶梯」。
- 「标题栏上不要显示标题。」（只留指示器，不写会话名。）
- 「指示器背后应该有 liquid glass」。
- 亮色模式下指示器看不清，要能用。
- 想在 App 里直接看到、切换 Palo 用的是什么模型（今天在终端里用 /model 才发现是 Sonnet）。
- 「普通会话上面那个胶囊首先没对齐，然后看起来太冗余，然后那个下面那行小字还出现了两遍。我希望这个胶囊是一个非常优雅的东西。」

## 详情页

- 「agent 详情页设计的非常的差。需要彻底的重新设计。」

## 手机

- 「主 agent 跟其他 agent 右上角的那个按钮不一样。」
- 「library 跟文件系统应该是两个固定的 tab。然后在手机上其他的东西应该都是模态的。放一个完整的多 tab 的浏览器进去，我不知道移动端怎么处理能让这个体验变得不过于复杂。」
- 「新建 session 的这个按钮的菜单里，可能需要能从历史记录来。」
- 「成果，是 per agent 的还是整个系统共享的？」（讨论结果：全局一份，在会话里默认只看这个会话的。）
- 「我希望能够左右滑动切换会话，我希望跟其他的手势没有冲突。因为在移动端已经没有分屏了，我需要一种快速切换的手段。」「可以参考 Bento Terminal 的 Focus 模式。就是，在底部加一个快速切换的 tab，这样既可以快速切换，又可以快速预览其他会话的状态。」
- 「手机的底部的快速切换不要这个图标，直接玻璃的颜色表示状态就好了」。

## 会话的工具

- 辅助会话要能自己发成果：「我们现在是需要把给主 agent 的这些工具也给辅助 agent，辅助 agent 要自己能够发 artifact。」
- 「会话之间能直接发话。这个应该是 CC 内置的功能。」

## Mac 上的问题

- 「Mac 上的侧边导航非常的不紧凑。」后来更正：「让你导航栏紧凑也只是让你做正常 mac 布局，现在过于紧凑丑的要命。你能就用系统默认的参数吗」
- 「mac 版上的标题栏完全没处理好。布局奇奇怪怪的」
- 「导航栏里选中项有的是强调色，太显眼了，导致 palo 的动画，一个状态 dot 的颜色都不显眼了」
- 「Mac 侧边栏的 session 没法拖动，应该是可以随意拖动排序，拖到另一个上边建立 workspace，也可以拖进拖出 workspace 的。」
- 「Mac workspace 视图性能非常差，拖动调整布局的时候简直卡炸了。在放开之前应该不需要任何真正的布局调整才对。这个模式下标题栏有两行，占了很多地方，实际上这个模式是想要尽可能紧凑的。我觉得分屏模式 composer 要矮一些。甚至 mac 上整体 composer 就太高了。然后在分屏状态下卡的要死，打字都打不顺」
- 「Mac 版左下角的创建会话按钮样式不对（非常奇怪），点了没反应。mac 版的设置按钮是黑色的，而不是玻璃颜色。滚动到底的气泡也是黑色的。」
- Mac 输入框里文字很长、换成多行后，鼠标滚轮在输入框里滚不动（家里人反馈）。
- 跟 Palo 说话时语音输入用不了（家里人反馈，设备待确认）。

## 第一版的教训

- 第一版一次合进很多改动，交给主人之前没有在真屏上走过一遍，带着这些问题：侧栏点不动、Mac 输入框占位符一直闪、亮色模式下指示器看不清。主人：「你他妈的怎么一个版本引入这么多新 bug，现在完全没法用了」。
- 重做时，每一版交给主人之前，都要先在 Mac 和 iPhone 上把基本操作走一遍：点侧栏、打字、打开详情、打开右侧栏。
